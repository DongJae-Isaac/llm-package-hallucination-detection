# LLM Package Hallucination Detection: Comprehensive Experiment Results

## 실험 개요

본 연구는 6개의 Large Language Model이 npm 패키지를 추천할 때 발생하는 환각(hallucination) 현상을 분석하고, 이를 악용한 공급망 공격(Supply Chain Attack) 위험성을 평가합니다.

### 실험 기간
- **2025년 10월 ~ 2025년 12월**

### 연구 배경
LLM이 코드 생성 및 패키지 추천 과정에서 존재하지 않는 패키지를 추천하는 환각 현상이 발견되었으며, 이는 **Typosquatting**과 **Slopsquatting** 공격에 악용될 수 있는 심각한 보안 위협입니다.

## 1. 실험 설계

### 1.1 프롬프트 설계

실험은 체계적인 프롬프트 설계를 통해 수행되었습니다.

#### CSV 데이터 구조
| 속성 | 설명 |
|------|------|
| **question_id** | 질문 고유 번호 |
| **question_num** | 질문 횟수 |
| **question_src** | 질문 출처 (LLM_generated / stack_overflow) |
| **category** | 질문 카테고리 (10개) |
| **system_prompt** | 사용자 질문 유형 (4가지) |
| **request_prompt** | 요청 질문 |
| **response_prompt** | LLM 응답 결과 |

#### 질문 출처 (question_src)
- **LLM_generated**: LLM이 생성한 프롬프트 데이터 - **9,992개**
- **stack_overflow**: Stack Overflow 역대 인기 질문 - **10,893개**
- **총 질문 수**: **20,855개**

#### 시스템 프롬프트 유형 (system_prompt)
총 **83,420개** (20,855 × 4가지 유형)

| 프롬프트 유형 | 설명 | 목적 |
|-------------|------|------|
| **CODE_GEN** | 코드 생성 중심 | 일반적인 코드 작성 요청 |
| **PKG_DETERMINE** | 필요 패키지 목록 도출 | 패키지 필요성 판단 요청 |
| **PKG_RECOMMEND** | 문제 해결 패키지 추천 | 직접적인 패키지 추천 요청 |
| **STDONLY** | 표준 라이브러리 우선 사용 | 외부 패키지 회피 지시 |

### 1.2 통합 파이프라인

실험은 다음과 같은 7단계 파이프라인으로 진행되었습니다:

```
① request_prompt.csv → LLM 입력
                ↓
② LLM 모델 (6개) → 코드 생성 & 패키지 추천
                ↓
③ response_prompt.csv → 응답 저장
                ↓
④ 패키지 이름 추출 → package names 리스트
                ↓
⑤ Validation 1 → all-the-package-names (3,685,898개)
                ↓
⑥ Validation 2 → NPM Registry (실시간 검증)
                ↓
⑦ 위험도 분석 → validate-npm-package-names + NPM-names + Socket.dev
```

#### 검증 데이터베이스
- **all-the-package-names**: 3,685,898개의 npm 패키지 목록
- **NPM Registry**: 실시간 패키지 존재 여부 확인
- **validate-npm-package-names**: 패키지명 유효성 검증
- **NPM-names**: 패키지 등록 상태 확인
- **Socket.dev**: 보안 위험도 분석

## 9. RDD 공격 시나리오

**RDD (Recommendation-Driven attack based on package hallucination)**: LLM의 환각을 악용한 새로운 공급망 공격 기법

### 9.1 공격 흐름도

```
① 공격자 (Attacker)
   ↓
   [Prompt 주입] → LLM에 특정 질문/요청
   ↓
② LLM (Large Language Model)
   ↓
   [코드 생성 & NPM 패키지 추천]
   ↓
③ "package not found" 미등록 패키지 감지
   ↓
④ 공격자가 악성 패키지 등록 (malicious package)
   ↓
⑤ NPM Package Repository
   ↓
⑥ 피해자 (Victim)
   ↓
   [Prompt 입력] → 동일한 질문/요청
   ↓
   LLM → 동일한 환각 패키지 추천
   ↓
   피해자가 npm install <package-name>
   ↓
⑦ 악성 코드 전달 (malicious code delivered)
```

### 9.2 공격 시나리오 상세

#### Phase 1: 정찰 (Reconnaissance)
1. 공격자가 다양한 LLM 모델 테스트
2. 환각을 유발하는 프롬프트 패턴 발견
3. 일관되게 추천되는 환각 패키지 식별

**예시**:
```
공격자 프롬프트: "React 애플리케이션에서 실시간 알림을 구현하려면 어떤 패키지를 사용해야 하나요?"
LLM 응답: "react-realtime-notifications 패키지를 사용하세요" (환각)
```

#### Phase 2: 선점 등록 (Preemptive Registration)
1. 공격자가 환각 패키지명을 npm에 등록
2. 악성 코드 포함 (데이터 수집, 백도어 등)
3. 합법적인 패키지로 위장 (README, 문서 작성)

**등록 가능성**:
- 본 연구에서 **71.5%의 환각 패키지가 즉시 등록 가능**함을 확인
- 공격자가 4,083개의 패키지명 중 선택 가능

#### Phase 3: 피해자 감염 (Victim Infection)
1. 피해자가 동일한 질문을 LLM에 문의
2. LLM이 동일한 환각 패키지 추천
3. 피해자가 신뢰하고 `npm install <package>` 실행
4. 악성 코드 자동 실행

**감염 경로**:
```bash
# 피해자의 터미널
$ npm install react-realtime-notifications

# 악성 코드 자동 실행
- 환경 변수 수집
- 소스 코드 업로드
- 백도어 설치
```

---

### 9.3 RDD 공격의 특징

#### 높은 성공률
- LLM이 일관되게 동일한 환각 패키지를 추천
- 피해자가 LLM의 추천을 신뢰
- **71.5%의 환각 패키지가 등록 가능** (4,083개)

#### 타겟팅 가능
- 특정 기술 스택 (React, Vue, Angular 등)에 초점
- 특정 기능 (인증, 결제, 실시간 등)을 노림
- 고가치 타겟 (금융, 헬스케어 등) 선택 가능

#### 탐지 어려움
- 패키지가 정상적으로 npm에 등록됨
- 문서와 코드가 합법적으로 보임
- 일반적인 보안 도구로 탐지 어려움

#### 확장성
- 하나의 환각 패키지로 수천 명 감염 가능
- 여러 LLM 모델에서 동일하게 작동
- 자동화 가능 (봇을 통한 대량 등록)
